# CampusPilot

Автоматический Telegram-помощник для расписания и поездок в ННГУ.

## Стек MVP

- Python 3.12
- Cloud Run Jobs
- Cloud Scheduler
- ННГУ RUZ API (основной источник расписания на старте)
- 2GIS Public Transport Routing API
- Telegram Bot API

## Что уже реализовано в каркасе

1. Получение недели расписания группы через `portal.unn.ru/ruzapi/schedule/group/{group_id}`.
2. Нормализация нескольких распространённых форматов ответа РУЗ.
3. Поиск ближайшего занятия с учётом корпуса.
4. Геокодирование домашнего адреса и адреса корпуса через 2GIS.
5. Запрос маршрутов общественного транспорта с точным временем отправления и учётом расписания.
6. Выбор самого позднего допустимого времени выхода из дома.
7. Отправка уведомления в Telegram без входящей команды.

## Важно по токену Telegram

Токен, присланный в чат, нельзя использовать как секрет для продакшна. Его следует отозвать через BotFather и создать новый. Новый токен хранить только в Secret Manager / переменной окружения и не помещать в Git.

## Переменные окружения

Скопировать `.env.example` в `.env` для локального теста.

Обязательные:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_CHAT_ID`
- `TWOGIS_API_KEY`
- `UNN_GROUP_ID` (для текущего примера: 50793)
- `HOME_ADDRESS`

Для первого MVP можно передавать корпус как адрес прямо в JSON-конфигурации `BUILDINGS_JSON`.

## Локальный запуск

```bash
python -m venv .venv
.venv\\Scripts\\activate
pip install -r requirements.txt
python -m app.main
```

## Как сейчас считается маршрут

- Система получает первую пару текущего дня.
- Целевое прибытие = начало пары минус `ARRIVAL_BUFFER_MINUTES`.
- Система пробует несколько моментов выхода из дома назад от дедлайна.
- Для каждого момента 2GIS строит маршрут на общественном транспорте с `start_time` и `enable_schedule=true`.
- Подходящий вариант должен прибыть не позже целевого времени.
- Из подходящих вариантов берётся максимально позднее время выхода.

Пока намеренно не включён отдельный realtime-поставщик транспорта: 2GIS уже умеет учитывать прогнозное/расписанное движение в расчёте маршрута. Позже можно добавить отдельный источник realtime без переписывания оптимизатора.
